## Gateway contract to prove before real closeout checks

1. One authoritative parent allocation covers shell, controller, Git/check/test children, authored negative controls and failures. Before a tool launch, reserve the entire reviewed process envelope, including the launch needed to do accounting itself. Record actual starts separately; unused reservations are not silently refunded. No independent child counter can authorize another parent launch.
2. Use fixed command plans and unique operation IDs. Preserve exclusive, numbered admission/exit receipts and refuse duplicate/missing/out-of-order consumption. Make the host wrapper use the tested gate; a helper tested in isolation is insufficient. No parallel launches or arbitrary shell command composition.
3. Route every optional commentary/excerpt/result through the parent reporting gateway. Serialize once, measure exact UTF-8 bytes, admit before display and preserve a separate closure reserve. Child capture storage and displayed excerpts have different counters; avoid counting an undisplayed log as displayed output or ignoring a second displayed copy. Retain bounded raw responses before formatting. Use supported host primitives; do not assume Node, Buffer, TextEncoder or an unverified slash command exists.
4. Reconcile parent admission receipts, actual host tool calls and child capture graphs. Fail on a missing/bypassed operation, an unknown descendant or uncertain ownership. Avoid external Git diff/textconv/pager/fsmonitor/submodule helpers and pytest plugin autoload. Report limits of descendant observation honestly; this is not machine-wide process accounting or OS confinement.
5. A stop disables optional dispatch but leaves preallocated closeout resources available. Each owned process has a direct retained handle/creation identity, bounded concurrent streams through both EOFs, timeout/teardown and reaped exit. No process is launched merely to print another process's status if its envelope was not reserved.

The execution package explicitly prepays **one initial acknowledgement of at most 512 UTF-8 bytes and one bootstrap shell/interpreter envelope of two starts**. Charge these once in the first ledger, including failure. This makes the host's required opening message/bootstrap visible without pretending a running gateway existed before it was created. Every later operation requires gateway admission.
